# DevForge 4.1.0 security review (hardening pass)

Scope: the extension code in this repository, reviewed and exercised in Chromium (e2e). Severity is
the impact if real; "Verified" means reproduced or measured, not assumed. Ranked most important
first. Nothing here was verified against a published build, a Web Store listing or any network
service other than local fixtures.

| # | Finding | Sev. | Evidence | Status |
| --- | --- | --- | --- | --- |
| 1 | **`window.__dfNet` exposed the Network capture log to every script on the page**, with unredacted URLs, headers and bodies. Page and third-party scripts could read, and could also change interception rules. | High | Read in the original `netcap.js` **and demonstrated in Chromium on the original and on the 4.0.x build** (a page script read captured requests). | **Fixed.** The log lives in a closure. A random, non-enumerable, non-configurable entry function is guarded by a 256-bit secret that is handed only to the isolated-world `netbridge.js` during a document_start handshake, then to the panel. Browser tests include a hostile page that tries to replay, enumerate, replace and re-handshake. `scripts/check.js` fails if the old name reappears. Residual: code running in the same JavaScript realm before `netcap.js` (i.e. nothing legitimate) could wrap built-ins first; stated in the README. |
| 2 | **Redirect pre-flight.** The earlier guard checked the first and final URL, but the browser had already sent the request to the redirect target by then. | Medium | Measured: the private target saw exactly one GET (no cookies) when redirects were followed. | **Fixed for recognisable private destinations; MITIGATED for the rest.** Redirects are not followed by default. When the user turns following on, a `declarativeNetRequest` session rule (lib/netguard.js, scoped to requests started by this extension) blocks every hop that names a private, loopback, link-local, unique-local or internal-looking host, before the request is sent. e2e: a raw `fetch` that follows the redirect fails with a network error and the private server sees 0 requests; with the rule removed (control) it sees 1. If the rule cannot be installed, following is refused. Residual: a public-looking name that resolves to a private address (DNS rebinding) is invisible to URL-based rules; the Security scan gate and the host-name check have the same limit. |
| 3 | **Guard failed open** when the page address was unknown (`if (pageUrl && …)`), disabling the private-address check. | Medium | Unit test failed before the fix. | **Fixed.** Unknown page → `blocked: the address of the page is unknown`. Unit and e2e tests. |
| 4 | **ReDoS in two detectors** (generic-secret regex: 80 KB → 2 s, quadratic; node-stack regex: 200 KB → 2.8 s). A hostile page could stall the panel. | Medium | Timed in Node. | **Fixed** with bounded quantifiers; regression tests and a fuzz timing test (worst case 39 ms). |
| 5 | **Runtime messages** to the panel were trusted by shape. | Low–Med | Read. | **Fixed.** `checkPanelMessage` validates sender (own extension id), type, tab, and handle format; forged and malformed messages are ignored (e2e). |
| 6 | **Saved reports loaded from Workspace** were rendered without validation. | Low | Read. | **Fixed.** `validateReport` normalises types and only keeps https references. |
| 7a | **`localhost.` (trailing dot) was not recognised as private**, so `blocksPrivate` allowed it. | Medium | Unit test failed before the fix. | **Fixed** (`lib/safe.js`), tests for `localhost.`, `*.local.`, decimal and IPv4-mapped forms. |
| 7 | **Private-host guard compared host names only, by pattern.** | Low–Medium | Read; adversarial matrix. | **FIXED + TEST (parsing) / MITIGATED (ports, DNS).** Hosts are now parsed (IPv4, IPv6 incl. IPv4-mapped, NAT64 and 6to4 embeddings, special-use ranges, trailing dots, malformed literals refused), and the same families are blocked at the network layer. Ports: a port number alone does not make a destination unsafe, so the page's own host is allowed on its own port and on ordinary dev ports, but not on well-known local admin ports (container engine, Elasticsearch, Consul, etcd, Kubernetes, RabbitMQ… `SENSITIVE_LOCAL_PORTS`). Different spellings of the same address (`127.0.0.1` vs `localhost`) count as different hosts. Residual: **DNS** (a public-looking name resolving to a private address) cannot be seen by an extension. |
| 8 | **Workspace was unencrypted** (IndexedDB); saved security reports describe a site's weaknesses. | Low | Verified. | **FIXED + TEST as an opt-in:** Owner mode can seal title/address/content of every item (AES-GCM, authenticated listing fields, verified in-place migration, reversible, reset keeps ciphertext). Default stays plain because encryption needs the passphrase to read your own work. Not protected: data while unlocked, a modified extension, or the plain backup you choose to download. |
| 9 | **Page built-ins can be replaced** (`String.prototype.charCodeAt`, `Function.prototype.call`, `JSON`, `crypto.getRandomValues`…). | see 10a | see 10a | see 10a |
| 10 | Unused `html` edit kind in the agent could run attribute handlers. | Low | Read; no caller in `panel/`. | **Fixed**: the kind is refused (AGENT_VERSION 7). |
| 10a | **Capture handshake window if `netcap.js` were injected mid-load.** `netcap.js` keeps a listener open until DOMContentLoaded when it starts while the document is loading, so a page script could ask for the key. | Low (currently unreachable) | Demonstrated by forcing `injectImmediately: true` in the browser: the key was obtainable. The panel never does this (default timing waits for the document), and a regression test fails if it ever does. | **Mitigated by construction and tested, not eliminated.** Reversing the registration order to close the window broke page-start capture (Chrome starts the MAIN-world script first), so it was reverted. |
| 10b | Until the document has loaded, a page script could send `netbridge.js` a *fake* key. | Low | Reasoned. | Accepted: it can only make capture unreachable; it never reveals the real key. |
| 10c | Dark-theme primary buttons: white text on the accent blue was 3.0:1. | Low (accessibility) | Computed. | **Fixed** (dark text, 6.4:1); light-theme accent, OK and warning text darkened to ≥ 5:1 on tinted backgrounds. |
| 10a | **The capture secret leaked to a page that replaces built-ins.** The entry function compared the secret with `String.prototype.charCodeAt` looked up at call time, so a page that replaced it received the 64-hex secret on every panel call, long after the handshake. | **High** (full read of the capture log and rule control) | **Reproduced in Chromium** on a fixture that hooks String/Array/Object/JSON/Function built-ins: the hook saw the secret. | **FIXED + TEST.** `netcap.js` now takes bound references (`uncurry`) at load and uses only those; the e2e test "poisons built-ins" fails if any replaced built-in ever receives the secret. **Residual (MITIGATED):** on-demand capture is injected after the page's own scripts, so a page that already replaced `crypto.getRandomValues`, `Function.prototype.bind` or the like *before* injection could weaken or observe the secret. This is inherent to running in the page's world; **page-start capture** (Settings → capture from page start) runs before any page script and is the strong mode. Reasoned from the platform model, not measured. |
| 10d | **No tests for the opener rule, stale caches, workspace sealing, agent hardening, or CI permissions.** | – | – | **FIXED:** `target=_blank` without `rel` is no longer reported (browsers isolate it); `rel=opener` and named targets are (e2e); downloads and `fetchInPage` use `no-cache` (unit + e2e with a changing, cacheable asset); `test/ci.test.js` keeps the workflow read-only. |
| 10e | **Findings from the line-by-line `agent.js` audit** (27 items, see docs/AGENT-AUDIT-LEDGER.md): quadratic `url(` regexes (3.5 s at 80 KB, minutes at 400 KB), script-free page save still containing live markup, handler stripping bypassable with `java<TAB>script:`, `@import` crash, forged events trusted by picker and recorder, `fetchInPage` limit optional, workflow limits, patch comment break-out, and more. | Medium (ReDoS, save) / low | partly run by reviewers, partly read | **FIXED + TEST** for the medium ones and most low ones; **UNRESOLVED:** form DOM-clobbering availability bugs (AG-22), `__df_bridge` id spoof (AG-16), pick mode when the panel closes (AG-27); **ACCEPTED:** text-undo re-parse (AG-12) |
| 11 | Sandbox `run` message sender was not checked. | Low | Read. | **Fixed**: only the embedding panel may start a run. |
| 12 | Obsolete `target=_blank` noopener rule; `force-cache` could serve stale export assets. | Low | Read. | **FIXED + TEST** (see 10d). |

Also checked: permissions (host access optional, one optional `cookies`), extension CSP, no
`innerHTML` with page data, CSV formula neutralisation, secret values masked in findings and
reports, the request gate under hostile inputs (`//host`, `/\host`, `data:`, `javascript:`,
credentials in URLs, dot segments, other ports).

Not covered: a line-by-line review of all of `agent.js`, the accessibility of every panel, behaviour
in browsers other than Chromium, and dynamic testing against real third-party sites.

## How to re-run the evidence

```sh
npm run verify   # syntax, references, 117 unit tests (node --test counts each test() once); `npm run lint`; `npm run a11y`
npm run e2e      # Chromium suite, including the capture-channel and hostile-page tests
```

## Status of everything, in one list

FIXED AND TESTED: 1, 3, 4, 5, 6, 7 (parsing), 8 (opt-in), 10a, 10d, 10e (most), 11, redirect guard (2, for recognisable private destinations).
MITIGATED, RESIDUAL RISK: 2 (DNS rebinding), 7 (DNS, spellings), 10a (on-demand injection after hostile page code), 10b (fake key during load can only disable capture).
UNRESOLVED: AG-16, AG-22, AG-27, `target=_blank` is fine but window.open-based opener leaks are not scanned.
NOT TESTED: browsers other than Chromium; screen readers; real 10-minute idle wait; secret-field redaction in the recorder.
